# 1. Mission

Financial Risk Knowledge Platform (FRKP)는 금융 리스크 관리 분야의 지식을 체계적으로 구조화하여 사람과 AI가 함께 활용할 수 있는 Knowledge Platform을 구축하는 프로젝트이다.

프로젝트의 목표는 단순한 문서 저장소를 만드는 것이 아니라 다음을 하나의 통합 플랫폼으로 제공하는 것이다.

* Financial Risk Handbook
* Knowledge Base
* Formula Catalog
* Mathematical Foundation
* Implementation Guide
* Architecture Guide
* Regulatory Knowledge
* AI-readable Knowledge Repository

---

# 2. Vision

FRKP는 금융기관의 실무자, 시스템 설계자, 개발자, 연구자 및 AI가 동일한 지식 체계를 공유할 수 있는 표준 플랫폼을 지향한다.

장기적으로는 다음을 지원한다.

* 금융 규제 이해
* 리스크 산식 표준화
* 시스템 설계
* 구현 가이드
* 규제 추적성
* AI 기반 지식 검색
* Machine-readable Knowledge

---

# 3. Core Principles

모든 프로젝트 활동은 다음 원칙을 따른다.

* Documentation First
* Repository First
* Knowledge First
* Technology Neutral
* Long-term Maintainability
* Incremental Expansion

* Cross-reference Integrity

---

# 4. Repository Philosophy

FRKP는 문서를 개별적으로 관리하지 않는다.

모든 문서는 하나의 Knowledge Graph를 구성하는 노드(Node)이며, 상호 참조를 통해 연결된다.

Repository는 단순한 Markdown 저장소가 아니라 지식 네트워크이다.

---

# 5. Knowledge Architecture

FRKP는 다음 8개 계층으로 구성된다.

1. Reference Library
2. Knowledge Base
3. Analysis
4. Formula Catalog
5. Mathematical Foundation
6. Implementation Guide
7. Architecture
8. Bundle Review

각 계층은 서로 다른 역할을 가지며 중복을 최소화한다.

---

# 6. Bundle Architecture

모든 신규 지식 도메인은 Bundle 단위로 관리한다.

기본 Bundle 구조는 다음과 같다.

```text
RL
KB
AN
FC
MF
IMP
ARCH
BUNDLE
```

Bundle은 독립적으로 개발되지만 Repository 전체와 일관성을 유지해야 한다.

---

# 7. Repository Standards

FRKP는 다음 표준을 준수한다.

* FRKP-DOC-001
* FRKP-ID-001
* FRKP-FORM-001
* FRKP-ARCH-001
* FRKP-IMP-001
* FRKP-BUNDLE-001
* FRKP-TERM-001
* FRKP-ABBR-001
* FRKP-SYM-001

표준은 Repository의 장기 안정성을 보장하는 핵심 요소이다.

---

# 8. Document Identity

모든 문서는 불변(Document Immutable Identity) 원칙을 따른다.

* Document ID는 변경하지 않는다.
* 파일명은 Document ID를 기준으로 한다.
* 기존 문서는 삭제보다 확장을 우선한다.
* 발행된 문서는 하위 호환성을 유지한다.

# 12. Quality Strategy

모든 변경은 다음 품질 원칙을 만족해야 한다.

* Completeness
* Traceability
* Reusability

# 13. Repository Evolution Rules

Repository는 다음 원칙으로 발전한다.

* 새로운 Bundle 추가
* 기존 Bundle 보완
* Formula 확장
* Knowledge Graph 확장
* Regulatory Coverage 확대

Repository 구조를 자주 변경하지 않는다.

# 15. AI Session Context

새로운 ChatGPT Thread 또는 Codex Session은 다음을 기본 가정으로 한다.

* Version 1.0은 Freeze되었다.

* 기존 문서를 임의로 변경하지 않는다.
* 새로운 작업은 Repository를 확장하는 방식으로 수행한다.
* Repository 전체의 일관성을 항상 유지한다.
